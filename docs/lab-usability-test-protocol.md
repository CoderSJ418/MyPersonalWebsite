# 交互实验室验证协议

> 对应 PRD v0.6 Phase 3.5 / T3-Owner。本文区分站点所有者验收、AI Proxy Review 与未来独立用户研究，三者不得混写。

## 当前发布门：Owner Acceptance

- 样本：1 名站点所有者；这是用户明确批准的个人项目验证例外。
- 补充证据：JoyCode 与 Claude Code 的 T3-Proxy，必须明确声明不代表真实用户测试。
- 通过要求：8/8 人工任务完成、0 个开放 P0/P1，并明确确认定位清楚、视觉有说服力、内容具有复用价值。
- 当前结果：2026-07-15 功能链路通过，但产品价值未通过；完成 Phase 3.5 后重测。

### Owner Acceptance 8 项任务

1. 10 秒内说明 Lab 的用途、目标用户和最强能力证据。
2. 在 30 秒内找到指定 Demo，并理解列表分类与搜索空状态。
3. 调整参数、观察平滑过渡、恢复默认值，并确认布局不跳动。
4. 复制使用方式和完整源码，确认就地反馈清楚且不推动内容。
5. 找到场景、禁用边界、搭配、实现、技术栈、性能、无障碍、兼容与授权。
6. 验证无效 ID 恢复、键盘操作、375px 纵向/横向和源码滚动。
7. 在首页、Projects、CTA 或项目指标中识别 Lab 效果的真实应用，并确认不干扰主内容。
8. 回答最突出效果、最困惑内容、最不满意体验和是否愿意公开发布。

## 未来研究债务：独立 5 人测试

- P1–P2：2 名招聘、用人经理或技术管理视角参与者。
- P3–P5：3 名前端开发者。
- 每人执行 5 个核心任务，共 25 个；3 名前端开发者各执行 1 个源码运行任务，共 3 个。
- 总任务数 28；通过线为至少 23/28（≥80%），并且没有阻断缺陷。

## 测试环境

- 只发送预发布直接 URL；不得添加公共导航、首页 CTA、Sitemap 或解除 `noindex`。
- 桌面 Chrome 执行主流程，其中至少 1 人补测 375px 移动视口。
- 参与者使用自己的语言口述想法；主持人不提示控件位置。
- 记录开始/完成时间、成功/失败、求助次数、观察与缺陷严重度。

## 每人 5 个核心任务

1. 首次打开 `/lab`，在 10 秒内说明这个专区的用途。
2. 在 30 秒内找到并打开主持人指定的 Demo。
3. 修改任意参数，并说明预览发生了什么变化。
4. 找到当前参数对应的“使用方式”。
5. 找到完整源码、MIT 许可证与兼容/降级说明。

## 前端开发者附加任务

6. 复制完整 SFC，在最小 Vue 3 + TypeScript 宿主中挂载；只允许使用页面声明的依赖。记录能否一次运行、缺失信息和修复耗时。

### 五人研究成功判定

- 无主持人指路，在时限内完成即成功。
- 口误后自行纠正、滚动查找不算失败；主持人提示控件位置或直接给答案算失败。
- P0 阻断：无法进入页面、源码不可运行、同意前发送 GA、键盘无法完成关键流程。
- P1 严重：任务失败但存在绕行；P2 一般：不阻断的理解或视觉问题。
- 任一渠道发现的 P0 未关闭时不得发布；未来五人研究不足 80% 时进入后续迭代，但不得反向声称本次个人项目发布已完成五人验证。
