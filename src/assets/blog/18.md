滚动动画最常见的实现，是每个模块进入视口时从下方淡入。它可以增加节奏，但重复十几次后不会形成叙事，只会让用户等待内容出现。

## 先区分三种需求

### 进入提示

元素首次进入视口时轻微出现，帮助用户感知页面继续向下展开。适合 `IntersectionObserver + CSS transition`，不需要持续读取滚动位置。

### 进度表达

时间线、阅读进度和步骤导航需要表达“当前走到哪里”。状态应来自可解释的滚动进度或激活区间，不是单纯播放一次动画。

### 叙事控制

复杂产品故事可能把滚动映射为时间轴，包含 pinned section、同步文本与视觉变化。这时才值得使用 GSAP ScrollTrigger 等工具，并设置严格动画预算。

三者混在一起，会让一个简单列表承担复杂时间轴成本。

## 进入提示的最小实现

```ts
const observer = new IntersectionObserver(
  (entries) => {
    for (const entry of entries) {
      if (!entry.isIntersecting) continue
      entry.target.classList.add('is-visible')
      observer.unobserve(entry.target)
    }
  },
  { threshold: 0.15 }
)
```

```css
.reveal {
  opacity: 0;
  transform: translateY(12px);
  transition: opacity 300ms ease, transform 300ms ease;
}

.reveal.is-visible {
  opacity: 1;
  transform: none;
}
```

位移不宜过大，时长不宜过长。内容应该在观察器失效时仍然可见，因此无 JavaScript 或 reduced-motion 状态要直接显示最终样式。

## Stagger 应来自信息关系

同一组卡片可以相隔 40–80ms 出现，表达它们属于一个序列。不同区域不应继承同一个不断累加的延迟，否则页面越往下等待越久。

```ts
const delay = Math.min(index * 60, 300)
```

设置上限比追求精确的“电影感”更重要。用户快速滚动时，应优先让内容可读。

## 进度线如何避免抖动

时间线可以按容器相对视口的位置计算 0–1 进度，再用 transform 缩放填充线。不要在每次滚动中遍历大量 DOM 并重复读取布局。

```ts
function updateProgress() {
  const rect = timeline.getBoundingClientRect()
  const travel = rect.height + window.innerHeight
  const progress = Math.min(1, Math.max(0, (window.innerHeight - rect.top) / travel))
  fill.style.transform = `scaleY(${progress})`
}
```

如果使用滚动监听，应通过 rAF 合并更新，并在组件卸载时移除监听和取消帧。

## 什么时候使用 GSAP

满足以下条件之一才考虑：

- 多个元素需要共享时间轴；
- 动画状态与滚动进度连续绑定；
- 需要 pin、scrub 或复杂序列；
- CSS 无法清楚表达；
- 团队能够维护生命周期与降级。

使用后必须在组件卸载时 kill tween 和 ScrollTrigger。路由切换十次后仍然存在旧实例，说明实现没有完成。

## reduced-motion 不是把时长调短

```css
@media (prefers-reduced-motion: reduce) {
  .reveal {
    opacity: 1;
    transform: none;
    transition: none;
  }
}
```

持续视差、缩放和位置跟随应停止。进度信息仍可用静态样式表达，不能因为关闭动画而隐藏内容。

## 性能预算

- 首屏只运行一组主要连续动画；
- 进入提示只播放一次并停止观察；
- 滚动回调不做网络请求和大数据计算；
- 动画优先使用 transform 与 opacity；
- 目标设备连续运行 30 秒无明显长任务；
- 触摸和低性能设备允许简化；
- 路由切换后监听器、rAF 和 GSAP 实例归零。

## 内容验收比动画验收更重要

1. 快速滚动时能否直接读到标题；
2. 动画失败时内容是否仍显示；
3. 键盘跳转锚点后是否被 sticky header 遮挡；
4. 移动横屏是否需要过多滚动才能读完一段；
5. 动画是否帮助理解顺序，而不是统一装饰；
6. 用户是否随时可以继续页面滚动。

滚动叙事的核心是组织注意力。只有当时间、位置和内容关系明确时，动画才真正参与表达。
