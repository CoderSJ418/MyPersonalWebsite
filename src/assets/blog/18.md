## 1. 滚动叙事的设计哲学

Framer Motion的滚动动画有一个核心思想：**内容不是一次性呈现的，而是随着用户滚动逐步展开**。这创造了"叙事感"——每个元素的出现都像故事的一个节拍。

关键不是"动画效果"，而是"信息节奏"：
- 用户滚动到某个区域 → 元素依次出现 → 创造注意力引导
- stagger延迟让元素不是"齐刷刷"出现，而是"一个接一个"
- 一次性触发（once）避免回滚时的重复动画干扰阅读

## 2. 技术选型：为什么不用GSAP

项目中已有GSAP用于ScrollTrigger，但我们选择用IntersectionObserver重新实现：

### 对比分析

| 维度     | GSAP ScrollTrigger           | IntersectionObserver + CSS |
| -------- | ---------------------------- | -------------------------- |
| 包体积   | ~25KB (gsap + ScrollTrigger) | 0KB (浏览器原生)           |
| 动画控制 | 精细（scrub, pin, timeline） | 基础（触发+过渡）          |
| 性能     | JS驱动，rAF调度              | CSS transition，合成线程   |
| 学习曲线 | 高（专有API）                | 低（标准Web API）          |
| 可维护性 | 依赖第三方库                 | 零依赖，永不过时           |

**决策**：对于"进入视口时触发一次过渡"这个场景，IntersectionObserver完全够用。GSAP ScrollTrigger更适合复杂的滚动驱动动画（如视差、pin），但我们不需要这些。

## 3. CSS过渡架构

### 3.1 状态模型

```
初始态: .vs-reveal (opacity: 0, translateY(20px))
可见态: .vs-reveal--visible (opacity: 1, translateY(0))
```

```css
.vs-reveal {
  opacity: 0;
  transform: translateY(20px);
  transition: opacity 0.6s cubic-bezier(0.25, 0.46, 0.45, 0.94),
              transform 0.6s cubic-bezier(0.25, 0.46, 0.45, 0.94);
}

.vs-reveal--visible {
  opacity: 1;
  transform: translateY(0);
}
```

**为什么是translateY(20px)？**
- 10px：太微妙，用户可能以为是渲染bug
- 20px：明确的上移感，传达"从下方浮现"
- 30px+：过于夸张，像弹入

### 3.2 Stagger延迟

```css
.vs-reveal--stagger {
  transition-delay: var(--stagger-delay, 0ms);
}
```

通过CSS变量`--stagger-delay`控制每个元素的延迟，而不是用JS的setTimeout：

```vue
<div
  v-for="(item, index) in items"
  :style="{ '--stagger-delay': `${index * 80}ms` }"
>
```

**为什么是80ms？**
- 50ms：延迟太短，stagger感不明显
- 80ms：刚好能感知到"依次出现"
- 120ms：延迟太长，用户等不及

### 3.3 延迟上限

长列表的stagger延迟必须有上限：

```typescript
// ❌ 危险：第20个元素延迟1600ms
const delay = index * 80

// ✅ 安全：延迟上限400ms
const delay = Math.min(index * 80, 400)
```

**为什么上限是400ms？**
- 300ms：用户能容忍的"即时反馈"上限
- 400ms：留出一点余量，stagger感仍存
- 500ms+：用户开始觉得"卡了"

## 4. Composable设计：useScrollReveal

```typescript
export function useScrollReveal(options: ScrollRevealOptions = {}) {
  const {
    threshold = 0.1,
    rootMargin = '0px 0px -40px 0px',
    once = true,
    staggerDelay = 80,
    maxStaggerDelay = 400,
  } = options

  let observer: IntersectionObserver | null = null

  const observe = (element: HTMLElement) => {
    if (!observer) {
      observer = new IntersectionObserver(
        (entries) => {
          entries.forEach((entry) => {
            if (entry.isIntersecting) {
              entry.target.classList.add('vs-reveal--visible')
              if (once) observer?.unobserve(entry.target)
            } else if (!once) {
              entry.target.classList.remove('vs-reveal--visible')
            }
          })
        },
        { threshold, rootMargin }
      )
    }
    observer.observe(element)
  }

  const observeChildren = (container: HTMLElement) => {
    const children = container.querySelectorAll('.vs-reveal')
    children.forEach((child, index) => {
      if (staggerDelay > 0) {
        const delay = Math.min(index * staggerDelay, maxStaggerDelay)
        ;(child as HTMLElement).style.setProperty('--stagger-delay', `${delay}ms`)
      }
      observe(child as HTMLElement)
    })
  }

  const disconnect = () => {
    observer?.disconnect()
    observer = null
  }

  return { observe, observeChildren, unobserve, disconnect }
}
```

### API设计原则

1. **observe**：观察单个元素
2. **observeChildren**：观察容器内所有.vs-reveal子元素，自动计算stagger
3. **once**：默认true，元素进入视口后停止观察（避免回滚时重复动画）
4. **staggerDelay/maxStaggerDelay**：stagger参数，0则禁用stagger

## 5. Vue指令：v-scroll-reveal

Composable适合复杂场景，但简单场景用指令更简洁：

```typescript
export const vScrollReveal: Directive = {
  mounted(el, binding) {
    const isStagger = binding.arg === 'stagger'
    const options = binding.value ?? {}
    
    el.classList.add('vs-reveal')
    if (isStagger) {
      el.classList.add('vs-reveal--stagger')
      if (options.index !== undefined) {
        el.style.setProperty('--stagger-delay', `${options.index * 80}ms`)
      }
    }
    
    const observer = new IntersectionObserver(
      ([entry]) => {
        if (entry.isIntersecting) {
          el.classList.add('vs-reveal--visible')
          observer.disconnect()
        }
      },
      { threshold: 0.1, rootMargin: '0px 0px -40px 0px' }
    )
    observer.observe(el)
  },
}
```

使用方式：

```vue
<!-- 简单reveal -->
<div v-scroll-reveal>内容</div>

<!-- stagger reveal -->
<div v-scroll-reveal:stagger="{ index: 2 }">内容</div>
```

## 6. 实际应用：BlogList

```vue
<script setup>
import { useScrollReveal } from '@/composables/useScrollReveal'

const listRef = ref(null)
const { observeChildren, disconnect } = useScrollReveal({
  threshold: 0.1,
  once: true,
  staggerDelay: 80,
  maxStaggerDelay: 400,
})

onMounted(() => {
  if (listRef.value) observeChildren(listRef.value)
})

onUnmounted(() => disconnect())
</script>

<template>
  <div ref="listRef">
    <!-- 精选区：卡片级stagger -->
    <article
      v-for="(post, index) in featuredPosts"
      class="vs-reveal vs-reveal--stagger"
      :style="{ '--stagger-delay': `${index * 80}ms` }"
    >
      <ContentCard :post="post" variant="blog-card" />
    </article>

    <!-- Feed区：列表级stagger（有上限） -->
    <article
      v-for="(post, index) in feedPosts"
      class="vs-reveal vs-reveal--stagger"
      :style="{ '--stagger-delay': `${Math.min(index * 80, 400)}ms` }"
    >
      <ContentCard :post="post" variant="blog-feed" />
    </article>
  </div>
</template>
```

## 7. 性能考量

### 7.1 IntersectionObserver的阈值

```typescript
threshold: 0.1 // 元素10%可见时触发
```

0.1是"刚好进入视口"和"不要太早触发"的平衡点。0意味着刚露边就触发，0.5意味着半数可见才触发。

### 7.2 rootMargin的负值

```typescript
rootMargin: '0px 0px -40px 0px' // 底部缩进40px
```

-40px意味着元素需要比视口底部多40px才能触发——给用户一点"滚动缓冲"，避免元素在视口边缘就触发动画。

### 7.3 once模式的Observer清理

```typescript
if (once) observer?.unobserve(entry.target)
```

一旦元素可见，立即停止观察。这有两个好处：
1. 减少Observer的计算开销
2. 避免回滚时重复触发动画（干扰阅读）

## 8. 总结

滚动叙事系统的核心设计：
- **零依赖**：IntersectionObserver + CSS transition，无第三方库
- **CSS驱动**：过渡效果全部由CSS完成，JS只负责触发
- **Stagger策略**：80ms/item，上限400ms，CSS变量驱动
- **双模式API**：Composable（复杂场景）+ Directive（简单场景）
- **一次性触发**：once模式避免回滚干扰，同时减少Observer开销
