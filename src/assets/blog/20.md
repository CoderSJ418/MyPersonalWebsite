Interaction Lab 最初很容易被做成十二张“看起来会动”的卡片。真正困难的是回答：用户为什么需要它、源码能否复制运行、效果是否在真实页面产生价值，以及如何证明发布没有破坏性能和可访问性。

这篇文章只记录已经在仓库和生产环境中验证的事实，不把代理测试写成真实用户研究。

## 1. 先把定位写进 PRD

Lab 面向两个用户：

- 访问作品集的人，希望快速判断作者的 UI、交互和前端工程能力；
- Vue 开发者，希望调参数、理解使用边界并复制可运行的 SFC。

这意味着每个 Demo 不能只有预览，还要具备：

```text
元数据
  ├─ 场景与不适用边界
  ├─ 技术栈和依赖
  ├─ 性能与无障碍说明
  └─ 授权与来源

实现
  ├─ 实际 Vue SFC
  ├─ 类型化参数
  ├─ reduced-motion 降级
  └─ 生命周期清理

交付
  ├─ 动态使用方式
  ├─ 完整源码
  ├─ 复制反馈
  └─ 最小宿主验证
```

没有这些约束，数量越多，只会增加重复实现和维护成本。

## 2. 注册表成为单一入口

每个效果由 JSON 元数据与类型化注册表描述，详情组件通过异步 import 按路由加载。Lab 首页只加载元数据和静态预览，不把十二个持续动画一起放进首屏。

注册表需要同时连接：

- 效果 ID 与路由；
- Demo 组件；
- raw SFC 源码；
- 参数默认值和控件；
- 预览资产；
- Sitemap；
- 许可证信息。

验证脚本检查这些对象一一对应，避免出现“卡片存在但路由缺失”或“源码与预览不是同一实现”。

## 3. 参数联动必须形成闭环

数字滚动 Demo 曾出现滑块已经变成 50000，使用代码也更新了，但预览仍停留在 98,234 的问题。它暴露了一个核心验收原则：

```text
参数控件
  → 响应式状态
  → 实际预览
  → 动态使用代码
```

四者必须使用同一状态源。自动测试不只断言 input 值，还要等待动画完成后检查最终显示值。

## 4. 可复制源码的标准比“有复制按钮”高

每个 SFC 都需要在独立 Vue 3.4 + Vite 5 宿主中验证。页面明确区分：

- 运行时依赖：组件实际 import 的包；
- 宿主工具链：Vite、Vue 插件、TypeScript 等构建环境。

复制成功和失败都提供视觉及 `aria-live` 反馈。剪贴板权限被浏览器拒绝属于受控失败状态，不能静默，也不能把权限限制误报成产品功能成功。

## 5. 展示效果必须在真实页面复用

如果 Lab 有一套 Magic Card，首页项目卡片又复制另一套相似代码，Demo 就只是孤立展品。项目最终让首页精选项目消费 canonical Magic Card 与 Number Ticker 实现。

复用不等于照搬表现强度。Lab 需要展示参数范围，首页卡片则使用更轻的中性边界和局部高光。共享的是行为与生命周期，消费者可以选择更克制的视觉配置。

## 6. 隐私优先的 GA4 事件

正式站只有在用户明确同意且未启用 Do Not Track 时加载 GA4。撤回后停止后续事件并清理项目可控标识。

事件使用封闭参数：

```text
lab_view        source
demo_open       effect_id, category
code_expand     effect_id
code_copy       effect_id, copy_target
lab_cta_click   placement
projects_cta_click placement
```

不发送搜索原文、代码内容和自由输入。事件系统的目标是判断 Lab 是否产生价值，不是尽可能多地收集数据。

## 7. 发布门禁如何组成

发布前执行：

- TypeScript 严格检查；
- ESLint check-only；
- 单元与集成测试；
- 覆盖率门禁；
- 生产构建与 Sitemap；
- Lab 注册表一致性；
- Playwright 路由、键盘、复制、移动端和同意门；
- Lighthouse；
- 独立 SFC 宿主构建；
- 桌面、移动、横屏和 reduced-motion 人工检查。

发布批次最终记录为：157 项单元/集成测试通过，Lab 专项 22 项通过，E2E 20 项通过；正式 `/lab` 的 Lighthouse Performance 为 90，Accessibility、Best Practices 与 SEO 为 100。

这些数字只证明对应协议下的结果，不能证明所有真实用户都会满意。

## 8. 自动化发现不了的产品问题

第一轮功能验收通过后，站点所有者仍然认为效果不够突出、页面偏淡、Demo 缺少使用场景和技术说明。于是项目增加 Phase 3.5，先解决内容深度和真实复用，再公开发布。

这个阶段最重要的决定是冻结 12 个效果，不用继续增加数量掩盖深度不足。先升级旗舰效果、补充使用边界并应用到真实页面。

## 9. AI Proxy 的正确位置

JoyCode 和 Claude Code 可以执行任务路径、测量触控尺寸和构建独立宿主，但报告必须标注 AI Proxy Review。它们不能替代真实用户研究。

个人项目暂时无法招募五名独立参与者，因此采用站点所有者验收例外，并把五人研究保留为未来债务。这比伪造“用户测试已通过”更可信。

## 10. 部署后的两个真实教训

### SPA 直链

本地路由正常不代表 Vercel 直接访问 `/lab` 正常。生产部署必须配置 SPA fallback，并逐个检查动态路由刷新。

### CTA 埋点

普通 anchor 触发整页导航时，事件可能在页面卸载前没有保留下来。内部 CTA 改为先记录事件，再通过 Vue Router 进行 SPA 跳转，并在正式 dataLayer 中验证事件参数。

## 可以复用到下一个项目的原则

1. PRD 先定义价值和边界，再列功能；
2. 展示型组件也要有真实消费者；
3. 源码交付必须独立构建验证；
4. 预览、参数和文档使用同一状态源；
5. 自动化证据与人工判断分开记录；
6. 数量冻结可以保护产品深度；
7. 生产验证不能由本地结果替代；
8. 分析事件受隐私与参数白名单约束；
9. 失败时回到对应阶段，不修改验收标准；
10. 不把 AI Review 冒充真实用户研究。

Interaction Lab 的最终价值不是 12 个效果，而是一条能把视觉想法变成可复用、可验证、可发布组件的交付链。
