暗色界面很容易通过发光、渐变和高对比边框制造视觉冲击，但作品集真正需要证明的是：在普通亮色页面里，信息是否仍然清楚，组件是否有一致层级，效果是否服务内容。

## 深度不是颜色深浅

亮色界面可以通过五个正交维度建立层次：

```text
Typography：标题、正文、辅助信息
Surface：页面、区块、卡片、浮层
Boundary：分隔线与交互边界
Spacing：内容关系与呼吸感
Motion：状态变化和注意力引导
```

每个维度只解决一类问题。不要同时用更粗标题、更深背景、更重阴影和动画强调同一个普通区块。

## 1. 先建立文字层级

一个稳定系统至少区分：

- 主标题：承担页面主题；
- 区块标题：帮助扫描；
- 正文：承担主要阅读；
- 辅助信息：日期、标签、说明；
- 操作文字：表达可点击动作。

层级差异主要来自字号、字重和间距，颜色只做辅助。把辅助文字降得过浅会牺牲可读性，也无法让主要内容真正更突出。

## 2. Surface 数量越少越容易维护

```css
:root {
  --us-bg-start: #ffffff;
  --us-surface: #ffffff;
  --us-surface-hover: #f8fafc;
  --us-border: rgb(15 23 42 / 8%);
}
```

业务组件应消费命名 Token，不在局部重新发明半透明白色。页面背景、普通卡片和 hover 表面已经能覆盖大多数场景；只有弹层或强调区域才需要更高层级。

## 3. 边界用于解释结构

边框适合：

- 输入框和按钮的可交互轮廓；
- 相邻表面难以区分时；
- 表格与代码区等确实需要网格结构的内容。

边框不适合：

- 每个标签、卡片、卡片内部区块全部描边；
- 用高饱和渐变持续包围普通内容；
- 同时叠加内阴影、外阴影和发光。

当边框太多时，先用间距和背景分组，再判断哪些轮廓仍然必要。

## 4. 间距表达关系

同组元素距离小，跨组距离大。比起在每个区块之间画线，稳定的垂直节奏更容易让用户理解结构。

```text
标题 ↔ 摘要：紧密
摘要 ↔ 标签：中等
卡片 ↔ 卡片：明确分隔
章节 ↔ 章节：最大间距
```

组件不应各自发明 18px、22px 等随机值。使用离散 spacing scale，页面调整时才能整体保持一致。

## 5. 运动只表达变化

亮色页面不需要用持续背景动画填满“空”。有价值的运动包括：

- 卡片展开后箭头与内容同步；
- 路由切换时保留方向感；
- 参数变化后预览立即响应；
- 复制后出现就地反馈；
- 内容进入时轻量提示阅读节奏。

运动预算应按视区管理：同一区域只有一个主效果，触摸和 reduced-motion 下提供稳定状态。

## 设计 Token 的职责

```text
原始值：颜色、字号、间距数字
语义 Token：accent、text-secondary、surface-hover
组件状态：card-hover、button-focus
```

业务组件优先使用语义 Token。原始品牌色变化时，不需要搜索所有组件；组件状态变化时，也不应该修改全局原始值。

## 从暗色系统迁移到单一亮色

如果产品已经决定只保留亮色，最干净的做法是删除主题切换状态和 `dark:` 分支，而不是把暗色变量留作“以后可能用”。

迁移顺序：

1. 固定亮色 Token 和对比度；
2. 移除切换入口和持久化偏好；
3. 删除主题 Store 与 DOM class；
4. 逐页清理暗色分支；
5. 回归 hover、focus、disabled 和错误状态；
6. 检查旧本地偏好不会重新影响页面；
7. 用静态搜索确认没有隐藏引用。

单一模式减少测试矩阵，也能迫使视觉系统在最常见的阅读环境中成立。

## 亮色页面验收清单

- 灰度截图中仍能区分标题、正文和辅助信息；
- 页面第一眼看到内容，不是容器轮廓；
- 交互元素有明确 focus；
- 阴影只表达真实层级；
- 表面 Token 数量可解释；
- 移动端没有连续“盒子墙”；
- reduced-motion 下结构不改变；
- 对比度达到 WCAG 2.2 AA；
- 删除动画和品牌色后，信息架构仍成立。

亮色设计的难点不是“少用颜色”，而是让每一种视觉信号都承担明确职责。层次来自系统，不来自特效数量。
