## 1. 设计意图：为什么需要光效系统

Stripe官网的卡片交互有一个标志性特征：鼠标移动时，卡片表面会出现一束柔和的光跟随鼠标移动。这个效果不是装饰——它传达了三个信息：

1. **可交互性**：光效暗示"这个元素是活的，可以点击"
2. **空间深度**：光在表面移动创造了微妙的3D感
3. **品质感**：流畅的光效传递工程品质的信号

## 2. 技术选型：为什么选择CSS变量驱动

实现鼠标追踪光效有三种路径：

### 方案A：JS直接操作style
```typescript
// ❌ 不推荐：JS与CSS耦合，难以维护
element.style.background = `radial-gradient(circle at ${x}px ${y}px, rgba(255,255,255,0.1), transparent 50%)`
```
**问题**：每帧都要计算gradient字符串，GC压力大，且无法与CSS transition配合。

### 方案B：Canvas渲染
```typescript
// ❌ 不推荐：过度工程，破坏语义化
ctx.clearRect(0, 0, width, height)
ctx.fillStyle = gradient
ctx.fillRect(0, 0, width, height)
```
**问题**：需要额外的Canvas层，破坏DOM语义，无法与CSS动画系统协作。

### 方案C：CSS变量驱动（最终选择）
```typescript
// ✅ 推荐：JS只设变量，CSS负责渲染
element.style.setProperty('--mouse-x', `${x}px`)
element.style.setProperty('--mouse-y', `${y}px`)
```
```css
/* CSS用变量渲染光效 */
.vs-card--light::before {
  background: radial-gradient(
    300px circle at var(--mouse-x) var(--mouse-y),
    rgba(255, 255, 255, 0.06),
    transparent
  );
}
```
**优势**：
- JS只负责坐标计算，CSS负责视觉渲染——职责分离
- CSS transition可以平滑过渡变量变化
- 浏览器合成线程优化CSS属性变化
- 零JS动画帧，无requestAnimationFrame开销

## 3. 光效物理模型

### 3.1 光源参数

| 参数     | 值                     | 设计理由                      |
| -------- | ---------------------- | ----------------------------- |
| 光源半径 | 300px                  | 覆盖卡片约1/3面积，不喧宾夺主 |
| 光源强度 | rgba(255,255,255,0.06) | 6%透明度，足够感知但不刺眼    |
| 衰减曲线 | linear → transparent   | 自然的光衰减感                |
| 边界溢出 | 50% extend             | 光源在边缘时仍有50%可见       |

### 3.2 伪元素架构

```css
.vs-card--light {
  position: relative;
  overflow: hidden; /* 裁剪溢出光效 */
}

.vs-card--light::before {
  content: '';
  position: absolute;
  inset: 0;
  /* 关键：z-index在内容下方 */
  z-index: 1;
  opacity: 0;
  transition: opacity 0.3s ease;
  pointer-events: none; /* 不阻挡鼠标事件 */
}

.vs-card--light:hover::before {
  opacity: 1;
}
```

**关键决策**：`pointer-events: none`确保伪元素不会拦截鼠标事件，否则mousemove会在伪元素上触发而不是卡片本身。

## 4. Composable设计：useMouseLight

```typescript
// src/composables/useMouseLight.ts
export function useMouseLight(
  targetRef: Ref<HTMLElement | null>,
  options: MouseLightOptions = {}
) {
  const { enabled = true, varPrefix = 'mouse', clearOnLeave = true } = options

  const isHovering = ref(false)

  const onMouseMove = (e: MouseEvent) => {
    if (!enabled || !targetRef.value) return
    const rect = targetRef.value.getBoundingClientRect()
    const x = e.clientX - rect.left
    const y = e.clientY - rect.top
    targetRef.value.style.setProperty(`--${varPrefix}-x`, `${x}px`)
    targetRef.value.style.setProperty(`--${varPrefix}-y`, `${y}px`)
    isHovering.value = true
  }

  const onMouseLeave = () => {
    isHovering.value = false
    if (clearOnLeave && targetRef.value) {
      targetRef.value.style.removeProperty(`--${varPrefix}-x`)
      targetRef.value.style.removeProperty(`--${varPrefix}-y`)
    }
  }

  return { isHovering, onMouseMove, onMouseLeave }
}
```

### API设计原则

1. **Ref输入**：接收`Ref<HTMLElement>`而非HTMLElement，与Vue 3模板ref天然配合
2. **varPrefix可配置**：支持多个光效实例使用不同变量名
3. **clearOnLeave**：鼠标离开时清除变量，配合CSS transition实现光效淡出
4. **零副作用**：不添加/移除事件监听器，由组件自行绑定

## 5. 性能考量

### 5.1 为什么不用requestAnimationFrame

mousemove事件本身已经由浏览器节流（通常60fps），额外用rAF包装只会增加延迟。CSS变量赋值是同步操作，浏览器会在下一次渲染前批量处理。

### 5.2 will-change的使用

```css
.vs-card--light::before {
  will-change: opacity; /* 仅对opacity做GPU层提升 */
}
```

**注意**：不要对`background`使用will-change，因为radial-gradient的变化会导致重绘而非合成。只对opacity（hover过渡）使用will-change。

### 5.3 事件委托 vs 直接绑定

对于列表场景（如博客卡片列表），考虑在父容器上使用事件委托：

```typescript
// 列表级事件委托（未来优化方向）
listRef.value.addEventListener('mousemove', (e) => {
  const card = (e.target as Element).closest('.vs-card--light')
  if (card) {
    const rect = card.getBoundingClientRect()
    card.style.setProperty('--mouse-x', `${e.clientX - rect.left}px`)
    card.style.setProperty('--mouse-y', `${e.clientY - rect.top}px`)
  }
})
```

## 6. 暗色模式适配

光效在暗色背景下更明显，在亮色背景下几乎不可见——这是符合预期的：

```css
/* 暗色模式：光效增强 */
[data-theme="dark"] .vs-card--light::before {
  background: radial-gradient(
    300px circle at var(--mouse-x) var(--mouse-y),
    rgba(255, 255, 255, 0.08), /* 暗色模式8% */
    transparent
  );
}

/* 亮色模式：光效减弱 */
[data-theme="light"] .vs-card--light::before {
  background: radial-gradient(
    300px circle at var(--mouse-x) var(--mouse-y),
    rgba(255, 255, 255, 0.03), /* 亮色模式3% */
    transparent
  );
}
```

## 7. 总结

CSS变量驱动的光效系统实现了：
- **零JS动画帧**：所有视觉渲染由CSS完成
- **职责分离**：JS计算坐标，CSS渲染光效
- **可组合性**：useMouseLight composable可在任何组件中使用
- **性能优先**：利用浏览器合成优化，无额外渲染开销

这套系统的核心思想是：**让JavaScript只做它最擅长的事（计算），让CSS做它最擅长的事（渲染）**。
