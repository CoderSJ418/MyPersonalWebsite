局部光效的作用不是证明页面“会跟随鼠标”，而是帮助用户知道哪张卡片正在响应、哪里可以继续操作。效果一旦比内容更醒目，就从反馈变成了噪声。

## 最小实现模型

JavaScript 只计算指针相对元素的位置，CSS 负责渲染：

```ts
function updatePointer(event: PointerEvent) {
  if (!(event.currentTarget instanceof HTMLElement)) return
  if (event.pointerType === 'touch') return

  const rect = event.currentTarget.getBoundingClientRect()
  const x = ((event.clientX - rect.left) / rect.width) * 100
  const y = ((event.clientY - rect.top) / rect.height) * 100

  event.currentTarget.style.setProperty('--pointer-x', `${x}%`)
  event.currentTarget.style.setProperty('--pointer-y', `${y}%`)
}
```

```css
.interactive-card {
  background:
    radial-gradient(
      circle at var(--pointer-x, 50%) var(--pointer-y, 35%),
      var(--us-accent-subtle),
      transparent 38%
    ),
    var(--us-surface);
}
```

这个结构有两个好处：业务状态不依赖指针位置，效果移除后组件仍然完整；视觉参数留在 CSS，设计调整不需要重写事件逻辑。

## 不要默认给 `pointermove` 加结论

不同浏览器和设备对输入事件的合并行为不同，不能简单声称事件天然固定在 60fps。是否需要 `requestAnimationFrame`，应通过 Performance 面板观察回调频率和主线程成本。

如果事件中只有坐标计算和两个 CSS 变量赋值，通常先保持简单。若同一页面有大量卡片或还伴随布局读取，可以把每帧最后一个位置写入 rAF：

```ts
let frameId = 0
let latestEvent: PointerEvent | null = null

function schedulePointer(event: PointerEvent) {
  latestEvent = event
  if (frameId) return

  frameId = requestAnimationFrame(() => {
    if (latestEvent) updatePointer(latestEvent)
    latestEvent = null
    frameId = 0
  })
}
```

组件卸载时要取消剩余 rAF。优化必须基于实际瓶颈，不能把包装 rAF 当成固定仪式。

## 触摸设备不需要模拟鼠标光源

触摸没有持续 hover 位置。为它监听移动坐标既浪费资源，也容易与页面滚动冲突。触摸端应保持稳定的静态表面，通过按压、焦点和展开状态提供反馈。

```css
@media (hover: none), (prefers-reduced-motion: reduce) {
  .interactive-card {
    --pointer-x: 50%;
    --pointer-y: 35%;
  }
}
```

JavaScript 同样应在初始化前检查触摸和 reduced-motion，而不是只依赖 CSS 隐藏结果。

## “边框光效”为什么容易显得重

当整圈边框持续使用高饱和渐变时，用户首先看到的是轮廓，而不是标题。真实项目卡片更适合：

- 默认使用中性、低对比边界；
- 指针附近才出现少量强调色；
- 阴影只表达层级，不叠加发光；
- 展开内容使用背景分组，避免每一层都有边框；
- 同一视区只保留一个主要连续效果。

Lab 演示可以把参数范围展示得更明显，嵌入首页时则应降低强度。两者共享实现，但消费者可以通过明确 props 或 embedded 状态选择表现层级。

## 性能验证方法

1. 在目标移动视口运行 30 秒；
2. 记录主线程是否出现大于 200ms 的长任务；
3. 快速跨越多张卡片，观察事件监听是否泄漏；
4. 切换路由 10 次，确认 rAF 和监听器被清理；
5. reduced-motion 下确认没有持续更新；
6. 检查光效关闭后，内容和焦点仍然清楚。

## 可访问性边界

局部光效不能是唯一交互提示。卡片如果可点击，应使用原生链接或按钮，提供可见焦点和明确名称。键盘焦点不经过指针，因此必须有独立的 `focus-visible` 状态。

最终判断很简单：关掉光效后，用户能否理解和完成任务？如果不能，问题不在动画参数，而在组件语义。
