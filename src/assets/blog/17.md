卡片“太重”通常不是单个边框颜色的问题，而是多个层级信号同时在抢注意力：实线边框、彩色描边、阴影、发光背景和内部子卡片一起出现，最终每一层都像主要内容。

## 卡片层级由四类信号组成

```text
边界：轮廓是否清楚
表面：卡片与页面背景是否有差异
深度：阴影和位移是否表达浮起
间距：内容是否形成自然分组
```

一个卡片不需要四类信号全部拉满。亮色作品集通常用轻边界加间距就能建立结构，hover 时再增加局部强调。

## 先判断卡片承担什么任务

### 信息分组卡

只负责把标题、摘要和标签组织在一起。默认不需要彩色边框和明显阴影，表面与背景有轻微差异即可。

### 交互入口卡

整张卡片可以打开详情，需要 hover、focus 和 active 状态。但强调应该发生在用户接近或聚焦时，不必持续显示。

### 旗舰展示卡

页面中数量很少，可以使用更强视觉效果。它不能与十几张普通卡共享同样强度，否则“旗舰”会失去意义。

## 一个实用的减法顺序

当卡片看起来很重时，不要立刻调透明度，按顺序删除信号：

1. 去掉内部每个区块的边框，用背景和间距分组；
2. 把标签从描边胶囊改为浅色表面；
3. 默认外边界改为中性 Token；
4. 阴影降到只表达一层高度；
5. 彩色光效只在指针附近或 focus 时出现；
6. 最后才调整圆角和整体留白。

这样能知道究竟是哪一层造成压迫，而不是同时改五个参数后凭感觉接受结果。

## 首页精选项目的合理结构

```text
项目标题 + 类型
  ↓
一句结果导向摘要
  ↓ 展开后
挑战 / 方案 / 影响
  ↓
可验证指标 + 技术栈 + 详情入口
```

默认折叠状态只需要清楚表达项目名称和类别。详细叙事展开后再出现，避免五张项目卡同时形成五个大色块。

## 边框 Token 应表达语义

```css
.project-card {
  border: 1px solid var(--us-border);
  background: var(--us-surface);
  box-shadow: var(--us-depth-1);
}

.project-card:hover,
.project-card:focus-within {
  border-color: var(--us-accent-border);
  box-shadow: var(--us-depth-1-hover);
}
```

不要在业务组件里重复写不同的 `rgba()`。边框强度应该由设计 Token 统一调整，消费者只选择状态。

## 展开交互需要避免布局惊跳

卡片展开后内容增加是预期变化，但控制按钮的位置和状态必须稳定：

- 箭头旋转，不改变按钮尺寸；
- 折叠与展开使用同一容器；
- “恢复默认值”等条件按钮应预留位置；
- 移动端展开后焦点仍在触发控件；
- 动画期间不锁住页面滚动；
- reduced-motion 下立即完成状态切换。

视觉顺滑不能牺牲语义。`aria-expanded` 与 `aria-controls` 应反映真实状态，整卡可点击时也要避免嵌套多个冲突交互区域。

## 移动端为什么更容易显重

窄屏下卡片接近满宽，连续边框会形成明显的“盒子墙”。可以通过减少卡片间距之外的视觉线条、让内部内容单列、增加标题与正文的垂直节奏来改善。

触控目标仍应至少 44px。不要为了轻盈把按钮缩小，也不要把文字颜色降到对比度不足。

## 一份视觉验收表

- 第一眼先看到项目标题，而不是边框；
- 五张卡片中没有五个持续动画；
- 默认、hover、focus、展开状态可区分；
- 关闭效果后信息层级仍成立；
- 内部标签和子卡片没有重复描边；
- 375px 下没有盒子堆叠压迫感；
- 键盘焦点比 hover 更明确；
- 对比度和触控尺寸不因“减法”下降。

卡片轻不等于透明度低。真正的轻，是每一种视觉信号只承担一个职责，并让内容始终拥有最高优先级。
