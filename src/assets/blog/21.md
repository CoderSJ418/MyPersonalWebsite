# Stripe/Framer/Raycast视觉特效深度拆解与落地实施

> 三大竞品的视觉特效不是"炫技"，而是设计语言的工程化表达。本文从设计本质出发，拆解15个标志性特效的底层技术逻辑，并给出基于Vue3+GSAP+TypeScript的完整落地路径。

---

## Part 1: 视觉特效拆解 — 设计语言与交互逻辑分析

### 1.1 三大竞品视觉本质对比

三大产品的视觉风格看似各不相同，但底层有清晰的设计哲学分野：

| 维度         | Stripe                          | Framer                     | Raycast                        |
| ------------ | ------------------------------- | -------------------------- | ------------------------------ |
| **核心隐喻** | 物理世界 — 光、深度、材质       | 流体 — 运动、节奏、变换    | 工具 — 紧凑、功能、响应        |
| **视觉本质** | 深度感 + 光感 + 精确            | 流动性 + 节奏 + 清晰       | 紧凑 + 功能 + 快速             |
| **动效哲学** | 微妙而精确，光随鼠标流动        | 流畅而有节奏，滚动驱动叙事 | 即时而弹性，状态切换零延迟     |
| **色彩策略** | 渐变为主，Mesh Gradient营造深度 | 紫-蓝渐变CTA，大面积留白   | 深色基底，边框光效，功能色点缀 |
| **交互模型** | 鼠标是光源，卡片是物理表面      | 滚动是时间轴，元素是节拍   | 键盘是入口，状态是弹簧         |
| **性能意识** | Canvas离屏渲染，CSS变量驱动     | CSS transition优先，IO触发 | 最小DOM操作，spring计算极简    |
| **信息密度** | 中等 — 每屏1-2个焦点            | 低-中 — 留白引导视线       | 高 — 紧凑网格，信息优先        |

**关键洞察**：三者不是在做"更好的动画"，而是在用动效表达各自的产品哲学——Stripe表达"精密与信任"，Framer表达"流畅与创造"，Raycast表达"效率与控制"。

### 1.2 15个特效详细拆解

#### Stripe 特效 #1: Mesh Gradient（流动渐变背景）

**视觉表现**：
Stripe首页背景不是静态渐变，而是一个持续流动的、有机形态的色彩场。色彩之间不是硬边界过渡，而是像流体一样缓慢混合、分离、再混合。整体感觉像极光或深海生物发光。

**推测技术方案**：
- **核心API**：Canvas 2D + Simplex Noise + `radialGradient` + `globalCompositeOperation = 'lighter'`
- **实现架构**：多个渐变圆心在Canvas上运动，每个圆心由Simplex Noise驱动位移，使用`lighter`混合模式叠加产生色彩融合

**关键实现逻辑**：

```
1. 创建全屏Canvas，position:fixed作为背景层
2. 初始化4-6个渐变球（gradient orb），每个有：
   - 位置(x,y) — 由Simplex Noise场驱动
   - 半径(r) — 150-400px
   - 颜色 — 从品牌色板取色，alpha 0.3-0.6
3. 每帧(60fps)：
   a. 用noise(x*time, y*time)更新每个球的位置
   b. 对每个球创建radialGradient(center, 0, center, radius)
   c. gradient.addColorStop(0, color_with_alpha)
   d. gradient.addColorStop(1, transparent)
   e. ctx.fillStyle = gradient
   f. ctx.globalCompositeOperation = 'lighter'
   g. ctx.fillRect(0, 0, width, height)
4. 使用离屏Canvas + willReadFrequently优化
```

**关键参数**：
- 球数量：4-6个
- 球半径：150-400px
- 移动速度：noise时间因子 0.0003-0.001
- alpha范围：0.3-0.6
- 混合模式：`lighter`（加色混合，产生光感）
- Canvas分辨率：0.5x DPR（性能优化）

#### Stripe 特效 #2: Cursor Light（鼠标追踪光效）

**视觉表现**：
鼠标移过卡片时，卡片表面出现一个柔和的径向光斑，光斑精确跟随鼠标位置。光斑不是简单的圆形高亮，而是有渐变衰减的"光照"效果，像手电筒照在磨砂玻璃上。

**推测技术方案**：
- **核心API**：CSS Custom Properties (`--mouse-x`, `--mouse-y`) + `radial-gradient` + `::before`伪元素
- **实现架构**：JS只负责更新CSS变量，所有视觉渲染由CSS完成

**关键实现逻辑**：

```
1. 监听卡片的mousemove事件
2. 计算鼠标相对卡片的位置：
   x = e.clientX - rect.left
   y = e.clientY - rect.top
3. 设置CSS变量：
   card.style.setProperty('--mouse-x', x + 'px')
   card.style.setProperty('--mouse-y', y + 'px')
4. CSS渲染（::before伪元素）：
   .vs-card--light::before {
     content: '';
     position: absolute;
     inset: 0;
     background: radial-gradient(
       600px circle at var(--mouse-x) var(--mouse-y),
       rgba(255,255,255,0.06),
       transparent 40%
     );
     opacity: 0;
     transition: opacity 0.3s;
   }
5. hover时opacity: 1，mouseleave时opacity: 0
```

**关键参数**：
- 光斑半径：600px（`radial-gradient`第一个参数）
- 光斑强度：`rgba(255,255,255,0.06)`（极低alpha，微妙感）
- 衰减距离：40%（从中心到40%半径处衰减到透明）
- 过渡时间：300ms opacity过渡
- CSS变量名：`--mouse-x` / `--mouse-y`

#### Stripe 特效 #3: Card 4-Layer Interaction（四层叠加交互）

**视觉表现**：
Stripe的卡片交互不是单一效果，而是四个视觉层同时响应鼠标，产生"物理表面"的错觉：
1. **Depth层**：鼠标移入时卡片微微抬起（shadow加深）
2. **Glow层**：卡片边框从暗色变为微光色
3. **Sweep层**：一个线性渐变光带从一侧扫过卡片表面
4. **Cursor层**：鼠标位置处出现径向光斑

四层叠加后，卡片看起来像一个被光照的3D物理表面。

**推测技术方案**：
- **核心API**：`box-shadow` + `border-color` transition + `linear-gradient`旋转 + CSS变量驱动光斑
- **实现架构**：每层用独立的CSS属性控制，通过hover和mousemove组合触发

**关键实现逻辑**：

```
Layer 1 — Depth（深度/阴影）:
  默认: box-shadow: 0 2px 8px rgba(0,0,0,0.2)
  hover: box-shadow: 0 8px 30px rgba(0,0,0,0.4)
  transition: box-shadow 0.3s ease

Layer 2 — Glow（边框光效）:
  默认: border-color: rgba(255,255,255,0.08)
  hover: border-color: rgba(99,102,241,0.4)
  transition: border-color 0.3s ease

Layer 3 — Sweep（光带扫过）:
  实现: background: linear-gradient(105deg, transparent 40%, rgba(255,255,255,0.05) 45%, rgba(255,255,255,0.1) 50%, rgba(255,255,255,0.05) 55%, transparent 60%)
  hover时: background-position从左移到右（或用@keyframes旋转角度）
  transition: background-position 0.6s ease

Layer 4 — Cursor（光标光斑）:
  同Cursor Light，用--mouse-x/y + radial-gradient
```

**关键参数**：
- Depth阴影偏移：2px→8px，模糊8px→30px
- Glow边框色：`rgba(255,255,255,0.08)` → `rgba(99,102,241,0.4)`
- Sweep光带角度：105deg
- Sweep光带宽度：40%-60%区间内5%宽度的亮带
- 各层过渡时间：Depth 300ms, Glow 300ms, Sweep 600ms, Cursor 300ms

#### Stripe 特效 #4: Scroll Counter（滚动计数器）

**视觉表现**：
当用户滚动到数据展示区域时，数字从0开始快速滚动到目标值，滚动速度先快后慢（easeOut），产生"数据在增长"的动态感。每个数字独立触发，形成stagger效果。

**推测技术方案**：
- **核心API**：IntersectionObserver + `requestAnimationFrame` + easeOutQuart缓动函数
- **实现架构**：IO触发 → rAF循环 → 缓动计算 → DOM更新

**关键实现逻辑**：

```
1. IntersectionObserver监听数字元素进入视口
2. 触发时记录：
   - startValue = 0
   - endValue = 目标值（从data属性读取）
   - startTime = performance.now()
   - duration = 2000ms
3. rAF循环：
   elapsed = now - startTime
   progress = Math.min(elapsed / duration, 1)
   easedProgress = easeOutQuart(progress)
   currentValue = startValue + (endValue - startValue) * easedProgress
   element.textContent = formatNumber(currentValue)
4. progress === 1时取消rAF

easeOutQuart(t) = 1 - Math.pow(1 - t, 4)
```

**关键参数**：
- 动画时长：2000ms
- 缓动函数：easeOutQuart（`1 - (1-t)^4`）
- IO阈值：0.3（30%可见时触发）
- 格式化：千分位分隔，或缩写（1.2M, 3.5K）
- stagger延迟：每个数字间隔150ms

#### Stripe 特效 #5: Gradient Text（渐变文字）

**视觉表现**：
标题文字不是纯色，而是带有流动渐变效果。渐变从一种颜色过渡到另一种，且渐变角度或位置持续变化，文字看起来在"发光"或"流动"。

**推测技术方案**：
- **核心API**：`background-clip: text` + `background-image: linear-gradient` + CSS `@keyframes`动画
- **实现架构**：纯CSS实现，JS零参与

**关键实现逻辑**：

```css
.gradient-text {
  background-image: linear-gradient(
    90deg,
    #6366f1,  /* indigo */
    #8b5cf6,  /* violet */
    #6366f1   /* indigo */
  );
  background-size: 200% 100%;
  background-clip: text;
  -webkit-background-clip: text;
  -webkit-text-fill-color: transparent;
  animation: gradient-shift 3s ease infinite;
}

@keyframes gradient-shift {
  0% { background-position: 0% 50%; }
  50% { background-position: 100% 50%; }
  100% { background-position: 0% 50%; }
}
```

**关键参数**：
- 渐变角度：90deg（水平流动）
- 渐变颜色：品牌色板2-3色
- `background-size`：200% 100%（确保渐变有移动空间）
- 动画时长：3s
- 动画缓动：ease infinite
- 降级：`-webkit-text-fill-color: transparent` + 标准fallback

#### Framer 特效 #6: Blue-Purple CTA（蓝紫渐变按钮）

**视觉表现**：
Framer的CTA按钮是一个从蓝到紫的渐变背景，hover时微微放大并产生更强的阴影光晕。过渡平滑，有一种"按钮在呼吸"的感觉。

**推测技术方案**：
- **核心API**：`background: linear-gradient` + `transform: scale()` + `box-shadow` + CSS transition
- **实现架构**：纯CSS，transition控制所有属性

**关键实现逻辑**：

```css
.cta-button {
  background: linear-gradient(135deg, #3b82f6, #8b5cf6);
  color: white;
  padding: 12px 32px;
  border-radius: 8px;
  transform: scale(1);
  box-shadow: 0 4px 15px rgba(99, 102, 241, 0.3);
  transition: transform 0.2s cubic-bezier(0.34, 1.56, 0.64, 1),
              box-shadow 0.2s ease;
}

.cta-button:hover {
  transform: scale(1.05);
  box-shadow: 0 8px 25px rgba(99, 102, 241, 0.5);
}
```

**关键参数**：
- 渐变方向：135deg
- 渐变颜色：`#3b82f6` → `#8b5cf6`
- hover scale：1.05
- hover阴影：4px/15px → 8px/25px，alpha 0.3→0.5
- 过渡缓动：`cubic-bezier(0.34, 1.56, 0.64, 1)`（弹性过冲）
- 过渡时长：200ms

#### Framer 特效 #7: Scroll Reveal Stagger（滚动显现交错）

**视觉表现**：
当用户滚动到某个区域时，多个元素不是同时出现，而是依次从下方淡入，形成一个"波浪"般的节奏感。每个元素的延迟不是固定的，而是基于某种策略（如距视口中心的距离）。

**推测技术方案**：
- **核心API**：IntersectionObserver + CSS `--delay`变量 + `@keyframes fadeInUp`
- **实现架构**：IO触发 → 添加visible类 → CSS变量控制delay → keyframes执行动画

**关键实现逻辑**：

```css
.reveal-item {
  opacity: 0;
  transform: translateY(20px);
  transition: opacity 0.5s cubic-bezier(0.16, 1, 0.3, 1),
              transform 0.5s cubic-bezier(0.16, 1, 0.3, 1);
  transition-delay: var(--delay, 0ms);
}

.reveal-item.visible {
  opacity: 1;
  transform: translateY(0);
}
```

```
JS部分：
1. IntersectionObserver监听容器
2. 子元素进入视口时：
   a. 计算每个元素距视口中心的距离
   b. 距离越远，--delay越大（最大200ms）
   c. 添加visible类
3. 一次性触发（once: true）
```

**关键参数**：
- 初始偏移：`translateY(20px)`
- 过渡时长：500ms
- 缓动：`cubic-bezier(0.16, 1, 0.3, 1)`（快速入场，无过冲）
- stagger策略：viewport-position（距中心越远delay越大）
- 最大delay：200ms
- IO阈值：0.1
- rootMargin：`0px 0px -40px 0px`

#### Framer 特效 #8: Image Ticker（图片循环滚动）

**视觉表现**：
一排Logo或图片以恒定速度水平滚动，当滚动到末尾时无缝衔接回开头，形成无限循环。hover时滚动暂停，方便查看。

**推测技术方案**：
- **核心API**：`translateX(-50%)` + 元素复制 + `animation: scroll linear infinite`
- **实现架构**：CSS animation驱动，DOM复制一份实现无缝

**关键实现逻辑**：

```html
<div class="ticker-wrapper">
  <div class="ticker-track">
    <!-- 原始内容 -->
    <img src="logo1.svg" />
    <img src="logo2.svg" />
    ...
    <!-- 复制一份，实现无缝 -->
    <img src="logo1.svg" />
    <img src="logo2.svg" />
    ...
  </div>
</div>
```

```css
.ticker-wrapper {
  overflow: hidden;
}

.ticker-track {
  display: flex;
  width: max-content;
  animation: ticker-scroll 30s linear infinite;
}

.ticker-track:hover {
  animation-play-state: paused;
}

@keyframes ticker-scroll {
  0% { transform: translateX(0); }
  100% { transform: translateX(-50%); }
}
```

**关键参数**：
- 滚动速度：30s完成一个完整周期
- 缓动：linear（匀速）
- 循环方式：translateX(-50%)，内容复制一份
- hover行为：`animation-play-state: paused`
- 降级：prefers-reduced-motion时暂停动画

#### Framer 特效 #9: Blur→Sharp（模糊到清晰）

**视觉表现**：
图片或内容块初始状态是模糊的，当滚动进入视口时，从模糊（blur 8px）过渡到清晰（blur 0）。效果像相机对焦，创造"揭示"的仪式感。

**推测技术方案**：
- **核心API**：`filter: blur()` + IntersectionObserver + CSS transition
- **实现架构**：IO触发 → 移除blur类 → CSS transition执行

**关键实现逻辑**：

```css
.blur-reveal {
  filter: blur(8px);
  opacity: 0.5;
  transform: scale(1.05);
  transition: filter 0.8s ease-out,
              opacity 0.8s ease-out,
              transform 0.8s ease-out;
}

.blur-reveal.visible {
  filter: blur(0);
  opacity: 1;
  transform: scale(1);
}
```

**关键参数**：
- 初始blur：8px
- 初始opacity：0.5
- 初始scale：1.05（微微放大，增强"推近"感）
- 过渡时长：800ms
- 缓动：ease-out
- IO阈值：0.2

#### Framer 特效 #10: 3D Card Hover（3D卡片悬停）

**视觉表现**：
鼠标悬停在卡片上时，卡片根据鼠标位置进行3D倾斜，鼠标在左侧卡片向左倾，在右侧向右倾。倾斜角度微妙（10-15度），配合阴影变化产生真实的3D感。

**推测技术方案**：
- **核心API**：`perspective` + `rotateX/Y` + mousemove计算
- **实现架构**：mousemove → 计算倾斜角度 → transform更新

**关键实现逻辑**：

```
1. 卡片容器设置 perspective: 1000px
2. mousemove事件：
   rect = card.getBoundingClientRect()
   centerX = rect.left + rect.width / 2
   centerY = rect.top + rect.height / 2
   mouseX = e.clientX - centerX
   mouseY = e.clientY - centerY
   rotateX = (mouseY / (rect.height / 2)) * -maxTilt  // 上移=正倾斜
   rotateY = (mouseX / (rect.width / 2)) * maxTilt    // 右移=正倾斜
3. card.style.transform = `perspective(1000px) rotateX(${rotateX}deg) rotateY(${rotateY}deg) scale(1.05)`
4. mouseleave时复位：transform = ''，transition: transform 0.5s
```

**关键参数**：
- perspective：1000px
- maxTilt：15deg
- hover scale：1.05
- 复位过渡：500ms power2.out
- glare效果：linear-gradient叠加（可选）

#### Raycast 特效 #11: Command Palette（命令面板）

**视觉表现**：
按⌘K时，一个半透明模糊背景的面板从屏幕中央缩放弹出（scale 0.98→1），带有搜索框和命令列表。背景使用backdrop-filter: blur产生毛玻璃效果。

**推测技术方案**：
- **核心API**：`backdrop-filter: blur(24px)` + `transform: scale(0.98→1)` + ⌘K键盘快捷键
- **实现架构**：键盘事件 → 状态切换 → CSS transition

**关键实现逻辑**：

```css
.command-palette-backdrop {
  position: fixed;
  inset: 0;
  background: rgba(0, 0, 0, 0.5);
  backdrop-filter: blur(4px);  /* 背景模糊 */
}

.command-palette {
  position: fixed;
  top: 20%;
  left: 50%;
  transform: translateX(-50%) scale(0.98);
  background: rgba(15, 15, 24, 0.85);
  backdrop-filter: blur(24px);  /* 面板自身毛玻璃 */
  border: 1px solid rgba(255, 255, 255, 0.08);
  border-radius: 12px;
  opacity: 0;
  transition: transform 0.2s cubic-bezier(0.34, 1.56, 0.64, 1),
              opacity 0.15s ease;
}

.command-palette.open {
  transform: translateX(-50%) scale(1);
  opacity: 1;
}
```

**关键参数**：
- 面板背景：`rgba(15, 15, 24, 0.85)` + `blur(24px)`
- 边框：`rgba(255, 255, 255, 0.08)`
- 入场scale：0.98 → 1
- 入场缓动：`cubic-bezier(0.34, 1.56, 0.64, 1)`（弹性）
- 入场时长：200ms
- 背景模糊：4px
- 快捷键：⌘K / Ctrl+K

#### Raycast 特效 #12: Fast State Toggle（快速状态切换）

**视觉表现**：
切换开关、标签选择等状态切换时，不是简单的0→1跳变，而是有一个轻微的"过冲→回弹"效果，模拟物理弹簧。过渡极快（150-200ms），但因为有弹性曲线，感觉比线性过渡更"活"。

**推测技术方案**：
- **核心API**：CSS transition + `cubic-bezier(0.34, 1.56, 0.64, 1)`弹性曲线
- **实现架构**：纯CSS transition，弹性缓动函数

**关键实现逻辑**：

```css

  transition: background-color 150ms cubic-bezier(0.34, 1.56, 0.64, 1);

.toggle-thumb {
  transition: transform 150ms cubic-bezier(0.34, 1.56, 0.64, 1);
}

  background-color: var(--accent);
}

.toggle-thumb.active {
  transform: translateX(20px);
}
```

**关键参数**：

  - 控制点1: (0.34, 1.56) — y值>1产生过冲
  - 控制点2: (0.64, 1) — 回弹到目标值
- 过渡时长：150ms
- 过冲量：约56%（1.56 - 1 = 0.56）
- 适用场景：toggle、tab切换、checkbox

## Part 2: 技术实现剖析 — 底层原理 + 动效库推荐 + 核心API

### 2.1 CSS动画原理：合成层优化与will-change

浏览器渲染管线中，动画性能的关键在于**哪些属性可以在合成线程（Compositor Thread）上处理，而不需要触发主线程的布局（Layout）和绘制（Paint）**。

#### 2.1.1 渲染管线与动画属性分类

```
JavaScript → Style → Layout → Paint → Composite
                        ↑         ↑        ↑
                    触发重排    触发重绘   仅合成
```

| 属性分类   | 触发阶段  | 性能        | 典型属性                                         |
| ---------- | --------- | ----------- | ------------------------------------------------ |
| **仅合成** | Composite | 60fps无压力 | `transform`, `opacity`                           |
| **重绘**   | Paint     | 中等开销    | `background-color`, `box-shadow`, `border-color` |
| **重排**   | Layout    | 高开销      | `width`, `height`, `top`, `left`, `margin`       |

**核心原则**：动画优先使用 `transform` 和 `opacity`，这两个属性可以被浏览器提升到合成层（Compositing Layer），由GPU直接处理，不触发Layout和Paint。

#### 2.1.2 合成层提升条件

浏览器在以下情况下会创建独立的合成层：

1. **3D transform**：`transform: translateZ(0)` 或 `transform: translate3d(0,0,0)`
2. **will-change**：`will-change: transform` 或 `will-change: opacity`
3. **position: fixed**：固定定位元素自动提升
4. **backdrop-filter**：毛玻璃效果自动提升
5. **video/canvas/iframe**：特定媒体元素自动提升
6. **opacity < 1 的动画**：正在动画中的半透明元素

#### 2.1.3 will-change使用规范

```css
/* ✅ 正确：在需要动画前设置，动画结束后移除 */
.card:hover {
  will-change: transform;
}
.card {
  transition: transform 0.3s ease;
}

/* ❌ 错误：全局设置will-change，浪费GPU内存 */
* {
  will-change: transform;  /* 每个元素都创建合成层！ */
}

/* ✅ 正确：JS动态控制 */
element.addEventListener('mouseenter', () => {
  element.style.willChange = 'transform, opacity'
})
element.addEventListener('transitionend', () => {
  element.style.willChange = 'auto'
})
```

**will-change的成本**：
- 每个合成层消耗GPU内存（约 width × height × 4 bytes × DPR）
- 过多合成层导致GPU内存压力，反而降低性能
- **规则**：同时存在的合成层不超过20个

#### 2.1.4 本项目中的合成层策略

```
| 场景                    | 策略                                                  |
| ----------------------- | ----------------------------------------------------- |
| Mesh Gradient Canvas    | Canvas自动独立层，无需will-change                     |
| Cursor Light (::before) | opacity动画 → hover时will-change: opacity             |
| Card 4-Layer            | transform + box-shadow → will-change: transform       |
| Scroll Reveal           | transform + opacity → will-change: transform, opacity |
| Gradient Text           | background-position动画 → 不需要will-change           |
```

#### 2.2.2 GSAP Easing函数选择指南

| 场景     | 推荐Easing            | 理由                       |
| -------- | --------------------- | -------------------------- |
| 入场动画 | `power3.out`          | 快速启动，缓慢停止，自然感 |

| 滚动驱动 | `none` (linear)       | 滚动进度直接映射           |
| 弹簧模拟 | `elastic.out(1, 0.3)` | 多次振荡衰减               |

#### 2.2.3 Vue3 + GSAP集成模式

本项目采用 **Composable封装模式**，将GSAP动画逻辑封装在composable中，组件通过composable API使用：

```typescript
// 模式1：Composable封装（本项目已有 — useGSAPAnimations.ts）
export function useGSAPAnimations() {
  const animations = ref<gsap.core.Tween[]>([])

  const fadeIn = (el: Element, config?: GSAPAnimationConfig) => {
    const tween = gsap.fromTo(el, { opacity: 0 }, { opacity: 1, ...config })
    animations.value.push(tween)
    return tween
  }

  // 组件卸载时清理所有动画
  onUnmounted(() => {
    animations.value.forEach(t => t.kill())
    animations.value = []
  })

  return { fadeIn, fadeInUp, ... }
}

// 模式2：Template Ref直接使用
const cardRef = ref<HTMLElement>()
onMounted(() => {
  gsap.from(cardRef.value!, { opacity: 0, y: 30, duration: 0.8 })
})

// 模式3：ScrollTrigger + Composable
export function useScrollAnimation() {
  onUnmounted(() => {
    ScrollTrigger.getAll().forEach(st => st.kill())
  })
}
```

**关键清理规则**：
- `onUnmounted` 中必须 `kill()` 所有 Tween 和 ScrollTrigger
- 否则组件销毁后动画仍在执行，导致内存泄漏和DOM引用错误
- 本项目 `useGSAPAnimations` 已实现此清理逻辑

### 2.3 Canvas2D动画：requestAnimationFrame与离屏优化

Mesh Gradient特效需要Canvas2D动画，其性能优化的核心在于**减少每帧的绘制工作量**。

#### 2.3.1 requestAnimationFrame循环架构

```typescript
// 标准rAF循环架构
let rafId: number | null = null
let lastTime = 0

const animate = (time: number) => {
  // 1. 计算deltaTime（用于帧率无关动画）
  const deltaTime = time - lastTime
  lastTime = time

  // 2. 更新状态
  updateState(deltaTime)

  // 3. 绘制
  draw()

  // 4. 继续循环
  rafId = requestAnimationFrame(animate)
}

// 启动
rafId = requestAnimationFrame(animate)

// 停止
if (rafId !== null) {
  cancelAnimationFrame(rafId)
  rafId = null
}
```

#### 2.3.2 离屏Canvas优化

```typescript
// 主Canvas（显示） + 离屏Canvas（绘制）
const mainCanvas = document.createElement('canvas')
const offscreen = document.createElement('canvas')
const mainCtx = mainCanvas.getContext('2d')!
const offCtx = offscreen.getContext('2d', { willReadFrequently: false })!

// 在离屏Canvas上绘制所有渐变球
function draw() {
  offCtx.clearRect(0, 0, width, height)
  offCtx.globalCompositeOperation = 'lighter'

  for (const orb of orbs) {
    const gradient = offCtx.createRadialGradient(
      orb.x, orb.y, 0,
      orb.x, orb.y, orb.radius
    )
    gradient.addColorStop(0, orb.color)
    gradient.addColorStop(1, 'transparent')
    offCtx.fillStyle = gradient
    offCtx.fillRect(0, 0, width, height)
  }

  // 一次性复制到主Canvas
  mainCtx.clearRect(0, 0, width, height)
  mainCtx.drawImage(offscreen, 0, 0)
}
```

**离屏Canvas的优势**：
- `willReadFrequently: false` 告知浏览器不需要频繁读取像素，启用GPU加速
- 一次性 `drawImage` 复制，减少主Canvas的重绘次数
- 离屏Canvas可以设置更低的分辨率（0.5x DPR）

#### 2.3.3 帧率控制与降级

```typescript
// 帧率控制：高端60fps，低端30fps
const TARGET_FPS = isLowEndDevice() ? 30 : 60
const FRAME_INTERVAL = 1000 / TARGET_FPS

const animate = (time: number) => {
  rafId = requestAnimationFrame(animate)

  const elapsed = time - lastTime
  if (elapsed < FRAME_INTERVAL) return  // 跳过此帧

  lastTime = time - (elapsed % FRAME_INTERVAL)
  updateAndDraw()
}
```

### 2.5 CSS变量驱动动画：--custom-property + JS setProperty模式

这是本项目最核心的动画架构模式——**JS负责计算，CSS负责渲染**。

#### 2.5.1 模式原理

```
┌─────────────┐     setProperty      ┌─────────────┐     读取变量      ┌─────────────┐
│  JavaScript  │ ──────────────────→ │  CSS变量     │ ──────────────→ │  CSS渲染     │
│  (计算位置)   │  --mouse-x: 120px  │  (数据桥梁)  │  var(--mouse-x) │  (radial-grad)│
└─────────────┘                      └─────────────┘                  └─────────────┘
```

**优势**：
1. **JS只做计算**：mousemove → 计算相对位置 → setProperty，无DOM操作
2. **CSS做渲染**：radial-gradient读取变量，浏览器自动重绘
3. **性能最优**：CSS变量变化不触发Layout，只触发Paint/Composite
4. **声明式**：CSS中直接用变量，样式逻辑集中管理

#### 2.5.2 本项目的CSS变量体系

```css
/* 光效系统 — useMouseLight / useGlobalLight */

--light-x: 45%;            /* 全局光源X位置（百分比） */
--light-y: 30%;            /* 全局光源Y位置（百分比） */
--light-active: 1;         /* 鼠标是否活跃 */

/* 方案A光感系统 */
--us-light-warm: rgba(255, 200, 100, 0.08);    /* 暖光 */
--us-light-cool: rgba(100, 150, 255, 0.06);    /* 冷光 */
--us-light-highlight: rgba(255, 255, 255, 0.1); /* 高光 */

/* 动效系统 — useScrollReveal */
--stagger-delay: 80ms;     /* 交错延迟 */
--reveal-easing: cubic-bezier(0.16, 1, 0.3, 1);  /* 入场缓动 */
--reveal-duration: 500ms;  /* 入场时长 */
```

#### 2.5.3 CSS变量 + transition 联动

```css
/* CSS变量本身不支持transition！但可以用@property注册实现过渡 */
@property --mouse-opacity {
  syntax: '<number>';
  inherits: false;
  initial-value: 0;
}

.vs-card--light::before {
  opacity: var(--mouse-opacity);
  transition: --mouse-opacity 0.3s ease;  /* 现在可以过渡了！ */
}
```

**注意**：`@property` 浏览器支持度约90%（Safari 15.4+），需要fallback：

```css
/* Fallback：直接用opacity过渡 */
.vs-card--light::before {
  opacity: 0;
  transition: opacity 0.3s ease;
}
.vs-card--light:hover::before {
  opacity: 1;
}
```

#### 2.5.4 CSS变量驱动的性能优势

| 方法                           | 触发阶段       | 是否需要JS动画循环 | 性能 |
| ------------------------------ | -------------- | ------------------ | ---- |
| JS直接操作style                | Layout + Paint | 是（rAF）          | 低   |
| CSS变量 + setProperty          | Paint          | 否（事件驱动）     | 高   |
| CSS变量 + @property transition | Composite      | 否（事件驱动）     | 最高 |
| GSAP动画                       | Layout + Paint | 是（rAF）          | 中   |

**结论**：对于鼠标跟随类动画（Cursor Light、Card 4-Layer的Cursor层），CSS变量驱动是最优方案。对于需要物理模拟的动画（弹簧、惯性），GSAP更合适。

### 2.6 技术选型决策矩阵

| 特效                  | 推荐技术                 | 理由                                 |
| --------------------- | ------------------------ | ------------------------------------ |

### 3.1 MeshGradientCanvas.vue — 流动渐变背景组件

**基于现有基础设施增强**：新建组件，使用方案A配色体系。

```vue
<!-- src/components/MeshGradientCanvas.vue -->
<template>
  <canvas
    ref="canvasRef"
    class="mesh-gradient-canvas"
    :style="{ opacity: isVisible ? 1 : 0 }"
  />
</template>

<script setup lang="ts">
/**
 * MeshGradientCanvas — Stripe级流动渐变背景
 *
 * 基于方案A配色：
 * - 基底: #08080D / #0F0F18
 * - 渐变球颜色: indigo/violet/cyan系，alpha 0.3-0.5
 *
 * 技术方案：
 * - Canvas 2D + Simplex Noise + radialGradient + lighter混合模式
 * - 离屏Canvas优化，0.5x DPR
 * - IntersectionObserver控制初始化（懒加载）
 * - prefers-reduced-motion检测（降级为静态渐变）
 */
import { ref, onMounted, onUnmounted } from 'vue'
import { isMobile } from '@/utils/deviceDetection'

// ============ Simplex Noise 简化实现 ============
// 生产环境建议使用 simplex-noise npm 包
// 此处为内联简化版，避免额外依赖

class SimplexNoise {
  private perm: number[]

  constructor(seed: number = 0) {
    const p = new Array(256)
    for (let i = 0; i < 256; i++) p[i] = i
    for (let i = 255; i > 0; i--) {
      seed = (seed * 16807 + 0) % 2147483647
      const j = seed % (i + 1)
      ;[p[i], p[j]] = [p[j], p[i]]
    }
    this.perm = [...p, ...p]
  }

  noise2D(x: number, y: number): number {
    const X = Math.floor(x) & 255
    const Y = Math.floor(y) & 255
    const xf = x - Math.floor(x)
    const yf = y - Math.floor(y)
    const u = xf * xf * (3 - 2 * xf)
    const v = yf * yf * (3 - 2 * yf)

    const aa = this.perm[this.perm[X] + Y]
    const ab = this.perm[this.perm[X] + Y + 1]
    const ba = this.perm[this.perm[X + 1] + Y]
    const bb = this.perm[this.perm[X + 1] + Y + 1]

    const x1 = aa / 255 * (1 - u) + ba / 255 * u
    const x2 = ab / 255 * (1 - u) + bb / 255 * u
    return x1 * (1 - v) + x2 * v
  }
}

// ============ 渐变球配置 ============
interface GradientOrb {
  x: number
  y: number
  radius: number
  color: string
  noiseOffsetX: number
  noiseOffsetY: number
  speed: number
}

// 方案A配色 — 渐变球颜色
const ORB_COLORS = [
  'rgba(99, 102, 241, 0.35)',   // indigo — accent色
  'rgba(139, 92, 246, 0.30)',   // violet
  'rgba(59, 130, 246, 0.25)',   // blue
  'rgba(6, 182, 212, 0.20)',    // cyan
  'rgba(99, 102, 241, 0.28)',   // indigo (第二个，不同alpha)
]

interface MeshGradientConfig {
  /** 渐变球数量 */
  orbCount?: number
  /** Canvas缩放比例（性能优化） */
  scale?: number
  /** 噪声速度因子 */
  noiseSpeed?: number
  /** 是否启用动画 */
  animated?: boolean
}

const props = withDefaults(defineProps<MeshGradientConfig>(), {
  orbCount: 5,
  scale: 0.5,
  noiseSpeed: 0.0003,
  animated: true
})

const canvasRef = ref<HTMLCanvasElement | null>(null)
const isVisible = ref(false)

let rafId: number | null = null
let noise: SimplexNoise
let orbs: GradientOrb[] = []
let width = 0
let height = 0
let ctx: CanvasRenderingContext2D | null = null
let offscreen: HTMLCanvasElement | null = null
let offCtx: CanvasRenderingContext2D | null = null
let time = 0
let observer: IntersectionObserver | null = null

// ============ 初始化渐变球 ============
function initOrbs() {
  orbs = []
  for (let i = 0; i < props.orbCount; i++) {
    orbs.push({
      x: Math.random() * width,
      y: Math.random() * height,
      radius: 150 + Math.random() * 250,
      color: ORB_COLORS[i % ORB_COLORS.length],
      noiseOffsetX: Math.random() * 1000,
      noiseOffsetY: Math.random() * 1000,
      speed: 0.5 + Math.random() * 0.5
    })
  }
}

// ============ 绘制帧 ============
function draw() {
  if (!ctx || !offCtx || !offscreen) return

  offCtx.clearRect(0, 0, width, height)
  offCtx.globalCompositeOperation = 'lighter'

  for (const orb of orbs) {
    if (props.animated) {
      orb.x += noise.noise2D(orb.noiseOffsetX + time * orb.speed, 0) * 2
      orb.y += noise.noise2D(0, orb.noiseOffsetY + time * orb.speed) * 2

      // 边界回弹
      if (orb.x < -orb.radius) orb.x = width + orb.radius
      if (orb.x > width + orb.radius) orb.x = -orb.radius
      if (orb.y < -orb.radius) orb.y = height + orb.radius
      if (orb.y > height + orb.radius) orb.y = -orb.radius
    }

    const gradient = offCtx.createRadialGradient(
      orb.x, orb.y, 0,
      orb.x, orb.y, orb.radius
    )
    gradient.addColorStop(0, orb.color)
    gradient.addColorStop(1, 'rgba(0, 0, 0, 0)')

    offCtx.fillStyle = gradient
    offCtx.fillRect(0, 0, width, height)
  }

  ctx.clearRect(0, 0, width, height)
  ctx.drawImage(offscreen, 0, 0)
}

// ============ 动画循环 ============
function animate() {
  time += props.noiseSpeed * 16
  draw()
  rafId = requestAnimationFrame(animate)
}

// ============ 检测reduced-motion ============
function prefersReducedMotion(): boolean {
  return window.matchMedia('(prefers-reduced-motion: reduce)').matches
}

// ============ 初始化Canvas ============
function initCanvas() {
  const canvas = canvasRef.value
  if (!canvas) return

  const scale = isMobile() ? 0.35 : props.scale
  width = window.innerWidth
  height = window.innerHeight

  canvas.width = width * scale
  canvas.height = height * scale
  canvas.style.width = '100%'
  canvas.style.height = '100%'

  ctx = canvas.getContext('2d', { willReadFrequently: false })
  if (!ctx) return
  ctx.scale(scale, scale)

  offscreen = document.createElement('canvas')
  offscreen.width = width * scale
  offscreen.height = height * scale
  offCtx = offscreen.getContext('2d', { willReadFrequently: false })
  if (offCtx) {
    offCtx.scale(scale, scale)
  }

  noise = new SimplexNoise(42)
  initOrbs()
  draw()

  if (props.animated && !prefersReducedMotion()) {
    animate()
  }
}

// ============ 清理 ============
function cleanup() {
  if (rafId !== null) {
    cancelAnimationFrame(rafId)
    rafId = null
  }
  if (observer) {
    observer.disconnect()
    observer = null
  }
}

// ============ 窗口resize处理 ============
let resizeTimer: number | null = null
function handleResize() {
  if (resizeTimer) clearTimeout(resizeTimer)
  resizeTimer = window.setTimeout(() => {
    cleanup()
    initCanvas()
    isVisible.value = true
  }, 200)
}

onMounted(() => {
  // IntersectionObserver懒加载
  observer = new IntersectionObserver(
    (entries) => {
      if (entries[0].isIntersecting) {
        isVisible.value = true
        initCanvas()
        observer?.disconnect()
      }
    },
    { threshold: 0 }
  )

  if (canvasRef.value) {
    observer.observe(canvasRef.value)
  }

  window.addEventListener('resize', handleResize)
})

onUnmounted(() => {
  cleanup()
  window.removeEventListener('resize', handleResize)
})
</script>

  top: 0;
  left: 0;
  width: 100%;
  height: 100%;
  pointer-events: none;
  z-index: 0;
  opacity: 0;
  transition: opacity 1s ease;
}
</style>
```

### 3.2 Card4LayerInteraction增强 — 基于useMouseLight

**基于现有 `useMouseLight.ts` 增强**：在现有Cursor Light基础上增加Depth、Glow、Sweep三层。

```typescript
// src/composables/useCard4Layer.ts
/**
 * useCard4Layer — Stripe级四层叠加卡片交互
 *
 * 基于现有useMouseLight增强，增加：
 * Layer 1 — Depth: box-shadow加深（hover触发）
 * Layer 2 — Glow: border-color变亮（hover触发）
 * Layer 3 — Sweep: linear-gradient光带扫过（hover触发）
 * Layer 4 — Cursor: radial-gradient光斑（mousemove触发，已有useMouseLight）
 *
 * 设计约束：
 * - 移动端禁用（isMobile/isTouch检测）
 * - prefers-reduced-motion: 只保留Depth和Glow，禁用Sweep和Cursor
 * - 所有过渡通过CSS transition，JS只负责状态切换
 */

import { ref, onMounted, type Ref } from 'vue'
import { isMobile, isTouch } from '@/utils/deviceDetection'

export interface Card4LayerConfig {
  /** Depth层阴影 — 默认态 */
  shadowDefault?: string
  /** Depth层阴影 — hover态 */
  shadowHover?: string
  /** Glow层边框色 — 默认态 */
  borderDefault?: string
  /** Glow层边框色 — hover态 */
  borderHover?: string
  /** Sweep层光带颜色 */
  sweepColor?: string
  /** 是否启用Sweep层 */
  enableSweep?: boolean
  /** 是否启用Cursor层 */
  enableCursor?: boolean
}

export function useCard4Layer(
  targetRef: Ref<HTMLElement | null>,
  config: Card4LayerConfig = {}
) {
  const {
    shadowDefault = '0 2px 8px rgba(0, 0, 0, 0.3)',
    shadowHover = '0 8px 30px rgba(0, 0, 0, 0.5)',
    borderDefault = 'rgba(255, 255, 255, 0.08)',
    borderHover = 'rgba(99, 102, 241, 0.4)',
    sweepColor = 'rgba(255, 255, 255, 0.06)',
    enableSweep = true,
    enableCursor = true
  } = config

  const isHovering = ref(false)
  const isEnabled = ref(!isMobile() && !isTouch())
  const prefersReducedMotion = ref(false)

  // Layer 4: Cursor — CSS变量驱动
  const onMouseMove = (e: MouseEvent) => {
    if (!isEnabled.value || !targetRef.value) return

    const rect = targetRef.value.getBoundingClientRect()
    const x = e.clientX - rect.left
    const y = e.clientY - rect.top

    targetRef.value.style.setProperty('--mouse-x', `${x}px`)
    targetRef.value.style.setProperty('--mouse-y', `${y}px`)
  }

  // Layer 1+2+3: Depth + Glow + Sweep — hover触发
  const onMouseEnter = () => {
    if (!isEnabled.value || !targetRef.value) return
    isHovering.value = true

    const el = targetRef.value

    // Layer 1: Depth
    el.style.setProperty('--card-shadow', shadowHover)
    // Layer 2: Glow
    el.style.setProperty('--card-border-color', borderHover)
    // Layer 3: Sweep
    if (enableSweep && !prefersReducedMotion.value) {
      el.style.setProperty('--sweep-position', '100% 0%')
    }
  }

  const onMouseLeave = () => {
    if (!isEnabled.value || !targetRef.value) return
    isHovering.value = false

    const el = targetRef.value

    // Layer 1: Depth复位
    el.style.setProperty('--card-shadow', shadowDefault)
    // Layer 2: Glow复位
    el.style.setProperty('--card-border-color', borderDefault)
    // Layer 3: Sweep复位
    if (enableSweep) {
      el.style.setProperty('--sweep-position', '-100% 0%')
    }
    // Layer 4: Cursor清除
    if (enableCursor) {
      el.style.removeProperty('--mouse-x')
      el.style.removeProperty('--mouse-y')
    }
  }

  // 初始化CSS变量
  const initCardStyles = () => {
    if (!targetRef.value) return
    const el = targetRef.value
    el.style.setProperty('--card-shadow', shadowDefault)
    el.style.setProperty('--card-border-color', borderDefault)
    el.style.setProperty('--sweep-position', '-100% 0%')
  }

  onMounted(() => {
    prefersReducedMotion.value = window.matchMedia(
      '(prefers-reduced-motion: reduce)'
    ).matches
    initCardStyles()
  })

  return {
    isHovering,
    isEnabled,
    onMouseMove,
    onMouseEnter,
    onMouseLeave
  }
}
```

### 3.3 useScrollCounter — 滚动计数器Composable

**新建composable**：基于IntersectionObserver + requestAnimationFrame + easeOutQuart。

```typescript
// src/composables/useScrollCounter.ts
/**
 * useScrollCounter — Stripe级滚动计数器
 *
 * 核心原理：
 * - IntersectionObserver检测元素进入视口
 * - requestAnimationFrame驱动逐帧更新
 * - easeOutQuart缓动：先快后慢，"数据在增长"的感觉
 * - 支持千分位格式化和缩写（1.2M, 3.5K）
 *
 * 设计约束：
 * - once模式：只触发一次
 * - prefers-reduced-motion: 直接设置目标值，无动画
 * - stagger支持：多个计数器交错触发
 */

import { ref, onMounted, onUnmounted, type Ref } from 'vue'

/** easeOutQuart缓动函数 */
function easeOutQuart(t: number): number {
  return 1 - Math.pow(1 - t, 4)
}

/** 千分位格式化 */
function formatWithCommas(value: number): string {
  return Math.round(value).toLocaleString('en-US')
}

/** 缩写格式化 */
function formatAbbreviated(value: number): string {
  const rounded = Math.round(value)
  if (rounded >= 1_000_000) {
    return (rounded / 1_000_000).toFixed(1) + 'M'
  }
  if (rounded >= 1_000) {
    return (rounded / 1_000).toFixed(1) + 'K'
  }
  return rounded.toString()
}

export type CounterFormat = 'comma' | 'abbreviated' | 'none'

export interface ScrollCounterOptions {
  /** 目标值 */
  endValue: number
  /** 起始值（默认0） */
  startValue?: number
  /** 动画时长（ms），默认2000 */
  duration?: number
  /** 格式化方式 */
  format?: CounterFormat
  /** 小数位数 */
  decimals?: number
  /** IO阈值 */
  threshold?: number
  /** stagger延迟（ms） */
  staggerDelay?: number
  /** 是否只触发一次 */
  once?: boolean
}

export function useScrollCounter(
  targetRef: Ref<HTMLElement | null>,
  options: ScrollCounterOptions
) {
  const {
    endValue,
    startValue = 0,
    duration = 2000,
    format = 'comma',
    decimals = 0,
    threshold = 0.3,
    staggerDelay = 0,
    once = true
  } = options

  const displayValue = ref(
    format === 'none'
      ? startValue.toFixed(decimals)
      : formatWithCommas(startValue)
  )
  const isCounting = ref(false)
  const hasCounted = ref(false)

  let rafId: number | null = null
  let startTime: number | null = null
  let observer: IntersectionObserver | null = null

  const formatValue = (value: number): string => {
    switch (format) {
      case 'comma': return formatWithCommas(value)
      case 'abbreviated': return formatAbbreviated(value)
      case 'none': return value.toFixed(decimals)
    }
  }

  const animate = (timestamp: number) => {
    if (startTime === null) startTime = timestamp

    const elapsed = timestamp - startTime
    const progress = Math.min(elapsed / duration, 1)
    const easedProgress = easeOutQuart(progress)
    const currentValue = startValue + (endValue - startValue) * easedProgress

    displayValue.value = formatValue(currentValue)

    if (progress < 1) {
      rafId = requestAnimationFrame(animate)
    } else {
      displayValue.value = formatValue(endValue)
      isCounting.value = false
      hasCounted.value = true
      rafId = null
    }
  }

  const startCounting = () => {
    if (hasCounted.value && once) return

    // reduced-motion降级
    if (window.matchMedia('(prefers-reduced-motion: reduce)').matches) {
      displayValue.value = formatValue(endValue)
      hasCounted.value = true
      return
    }

    isCounting.value = true
    startTime = null
    rafId = requestAnimationFrame(animate)
  }

  const stopCounting = () => {
    if (rafId !== null) {
      cancelAnimationFrame(rafId)
      rafId = null
    }
    isCounting.value = false
  }

  onMounted(() => {
    observer = new IntersectionObserver(
      (entries) => {
        if (entries[0].isIntersecting) {
          if (staggerDelay > 0) {
            setTimeout(startCounting, staggerDelay)
          } else {
            startCounting()
          }
          if (once) observer?.unobserve(entries[0].target)
        } else if (!once) {
          stopCounting()
          displayValue.value = formatValue(startValue)
          hasCounted.value = false
        }
      },
      { threshold }
    )

    if (targetRef.value) {
      observer.observe(targetRef.value)
    }
  })

  onUnmounted(() => {
    stopCounting()
    observer?.disconnect()
  })

  return {
    displayValue,
    isCounting,
    hasCounted,
    startCounting,
    stopCounting
  }
}
```

## Part 4: 性能与约束 — 防抖/懒加载/GPU加速 + 降级策略

> 视觉特效的工程化不仅是"实现效果"，更是"在约束条件下可靠地实现效果"。没有性能预算的特效是技术债。

### 4.1 防抖策略：mousemove 16ms节流 + scroll rAF节流

#### 4.1.1 mousemove节流

鼠标移动事件在高精度鼠标上每秒可触发数百次，直接在回调中执行计算会导致主线程阻塞。

```typescript
/**
 * mousemove节流 — 16ms（约60fps）
 *
 * 原理：记录上次执行时间，间隔不足16ms时跳过
 * 为什么不用requestAnimationFrame？
 *   - rAF的回调在下一帧执行，增加一帧延迟
 *   - mousemove需要即时响应，16ms节流更合适
 *   - rAF适合连续动画，不适合事件节流
 */

function createThrottledMouseMove(
  callback: (e: MouseEvent) => void,
  throttleMs: number = 16
): (e: MouseEvent) => void {
  let lastTime = 0

  return (e: MouseEvent) => {
    const now = performance.now()
    if (now - lastTime < throttleMs) return
    lastTime = now
    callback(e)
  }
}

// 使用示例
const throttledHandler = createThrottledMouseMove((e) => {
  const rect = card.getBoundingClientRect()
  const x = e.clientX - rect.left
  const y = e.clientY - rect.top
  card.style.setProperty('--mouse-x', `${x}px`)
  card.style.setProperty('--mouse-y', `${y}px`)
})

card.addEventListener('mousemove', throttledHandler)
```

**本项目中的应用**：
- `useMouseLight.ts`：当前直接在mousemove中setProperty，建议增加16ms节流
- `useCard4Layer.ts`：Layer 4的Cursor层需要16ms节流
- `useGlobalLight.ts`：已有RAF lerp惯性，不需要额外节流

#### 4.1.2 scroll事件rAF节流

```typescript
/**
 * scroll rAF节流
 *
 * 原理：使用requestAnimationFrame将scroll回调延迟到下一帧
 * 每帧只执行一次，避免scroll事件的高频触发
 */

function createRafScrollHandler(
  callback: () => void
): () => void {
  let ticking = false

  return () => {
    if (ticking) return
    ticking = true
    requestAnimationFrame(() => {
      callback()
      ticking = false
    })
  }
}

// 使用示例
const rafScrollHandler = createRafScrollHandler(() => {
  // 更新scroll-driven动画
  updateParallax()
  updateScrollProgress()
})

window.addEventListener('scroll', rafScrollHandler, { passive: true })
```

**关键细节**：
- `{ passive: true }` 告知浏览器不会调用 `preventDefault()`，允许滚动优化
- `ticking` 标志确保每帧只执行一次
- 本项目的 `useScrollReveal.ts` 使用IntersectionObserver而非scroll事件，无需此节流

#### 4.1.3 resize防抖

```typescript
/**
 * resize防抖 — 200ms
 *
 * 原理：resize期间持续清除定时器，停止resize后200ms执行
 * 避免Canvas重绘等高开销操作在resize过程中频繁执行
 */

function createDebouncedResize(
  callback: () => void,
  delayMs: number = 200
): () => void {
  let timer: number | null = null

  return () => {
    if (timer) clearTimeout(timer)
    timer = window.setTimeout(callback, delayMs)
  }
}
```

### 4.4 降级策略：prefers-reduced-motion + 低端设备feature detection

#### 4.4.1 prefers-reduced-motion检测

```typescript
/**
 * 全局reduced-motion检测
 *
 * 策略分级：
 * - Level 0（完全禁用）：Mesh Gradient停止动画，所有transition设为0ms
 * - Level 1（保留基本）：禁用装饰性动画，保留功能性过渡
 * - Level 2（全部启用）：所有动画正常
 */

export function getMotionPreference(): 0 | 1 | 2 {
  if (typeof window === 'undefined') return 2

  const mq = window.matchMedia('(prefers-reduced-motion: reduce)')
  if (mq.matches) {
    // 检测是否是"减少动画"而非"禁用动画"
    const mqStrict = window.matchMedia('(prefers-reduced-motion: reduce) and (update: slow)')
    return mqStrict.matches ? 0 : 1
  }
  return 2
}
```

#### 4.4.3 低端设备Feature Detection

```typescript
/**
 * 低端设备检测
 *
 * 指标：
 * 1. hardwareConcurrency — CPU核心数 < 4
 * 2. deviceMemory — 内存 < 4GB
 * 3. WebGL renderer — 包含"SwiftShader"（软件渲染）
 * 4. 连接类型 — slow-2g / 2g
 */

export interface DeviceCapability {
  isLowEnd: boolean
  cores: number
  memory: number
  isSoftwareRenderer: boolean
  connectionType: string
}

export function detectDeviceCapability(): DeviceCapability {
  const cores = navigator.hardwareConcurrency || 4
  const memory = (navigator as any).deviceMemory || 4
  const connection = (navigator as any).connection?.effectiveType || '4g'

  // 检测软件渲染
  let isSoftwareRenderer = false
  try {
    const canvas = document.createElement('canvas')
    const gl = canvas.getContext('webgl')
    if (gl) {
      const renderer = gl.getParameter(gl.RENDERER)
      isSoftwareRenderer = renderer.includes('SwiftShader')
    }
  } catch {
    isSoftwareRenderer = true
  }

  const isLowEnd =
    cores < 4 ||
    memory < 4 ||
    isSoftwareRenderer ||
    connection === 'slow-2g' ||
    connection === '2g'

  return {
    isLowEnd,
    cores,
    memory,
    isSoftwareRenderer,
    connectionType: connection
  }
}
```

```typescript
  const measure = () => {
    frameCount++
    const now = performance.now()

    if (now - lastTime >= 1000) {
      fps.value = frameCount
      frameCount = 0
      lastTime = now

      // FPS低于30时自动降级
      if (fps.value < 30 && !shouldDegrade.value) {
        shouldDegrade.value = true
        console.warn('[Performance] FPS dropped below 30, degrading effects')
      }

      // FPS恢复到45以上时恢复
      if (fps.value > 45 && shouldDegrade.value) {
        shouldDegrade.value = false
      }
    }

    rafId = requestAnimationFrame(measure)
  }

  onMounted(() => {
    // 仅在开发环境或显式启用时监控
    if (import.meta.env.DEV) {
      rafId = requestAnimationFrame(measure)
    }
  })

  onUnmounted(() => {
    if (rafId !== null) cancelAnimationFrame(rafId)
  })

  return { fps, shouldDegrade }
}
```

## 总结：从拆解到落地的完整路径

本文从三大竞品的视觉哲学出发，拆解了15个标志性特效的技术底层，并给出了基于Vue3+GSAP+TypeScript的完整落地方案。核心要点：

1. **设计语言先行**：Stripe=深度感+光感+精确，Framer=流动性+节奏+清晰，Raycast=紧凑+功能+快速。特效不是炫技，是设计语言的工程化表达。

2. **优先级驱动**：P0（Mesh Gradient + Cursor Light + Card 4-Layer）形成"光-深-层"三位一体，是方案A深色基底的灵魂。P1/P2/P3按需迭代。

3. **基于现有基础设施增强**：useMouseLight → useCard4Layer，useScrollReveal → 已有viewport-position stagger，useCard3D → 默认配置即匹配。不从零构建。

4. **CSS变量驱动架构**：JS计算位置，CSS渲染效果。这是Cursor Light和Card 4-Layer的核心模式，性能最优。

5. **性能预算不可妥协**：60fps目标、2ms mousemove预算、8MB Canvas内存预算。prefers-reduced-motion和低端设备降级是必须，不是可选。

6. **渐进增强**：先实现核心特效（P0），验证性能，再逐步增加。每个特效都有独立的降级策略，确保在任何设备上都有可接受的体验。
