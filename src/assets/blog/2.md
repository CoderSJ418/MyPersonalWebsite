> 本文是 2026 年回看 Vue 3.5 的工程笔记。判断一个版本是否重要，不看新增 API 数量，而看它是否减少了长期维护中的隐性错误。

Vue 3.5 没有改变 Vue 3 的基本使用方式，但它处理了几个很实际的问题：响应式系统的内存与依赖追踪、Props 解构丢失响应性、模板引用类型不稳定，以及 watcher 中异步副作用难以清理。

## 1. 响应式内核优化：用户无感，工程有收益

官方发布说明提到，3.5 重构了响应式系统，在保持行为一致的前提下降低内存占用，并修复部分嵌套计算属性出现“陈旧值”的情况。

这类优化不应该成为升级宣传中的性能承诺。正确做法是：

1. 先升级测试环境；
2. 覆盖 computed 链、数组更新和大列表场景；
3. 比较内存与交互指标；
4. 不因为底层更快就放松组件拆分和数据规模控制。

框架优化是安全余量，不是业务无限增加响应式对象的许可证。

## 2. 响应式 Props 解构：写法更自然，但边界要清楚

```vue
<script setup lang="ts">
interface Props {
  count?: number
  label: string
}

const { count = 0, label } = defineProps<Props>()

watchEffect(() => {
  console.log(label, count)
})
</script>
```

在 Vue 3.5 的编译转换下，`defineProps` 解构出的变量仍会跟随父组件更新。它减少了 `props.count` 的重复书写，也让默认值更接近普通 TypeScript。

需要注意：这依赖 `<script setup>` 编译语义。把变量传给要求 `Ref` 的组合函数时，不要假设它天然就是 ref；可以传 getter：

```ts
useFeatureValue(() => count)
```

## 3. `useTemplateRef`：让 DOM 引用与模板名称对齐

```vue
<script setup lang="ts">
import { onMounted, useTemplateRef } from 'vue'

const searchInput = useTemplateRef<HTMLInputElement>('search-input')

onMounted(() => searchInput.value?.focus())
</script>

<template>
  <input ref="search-input" type="search" />
</template>
```

旧写法需要手动声明与模板同名的 `ref(null)`。`useTemplateRef` 明确表达“这是模板引用”，也降低了变量重命名后模板和脚本不一致的概率。

不要因此扩大直接 DOM 操作。能用声明式状态解决的问题仍然交给 Vue；模板引用适合焦点管理、尺寸测量和第三方库挂载等确实需要元素实例的场景。

## 4. `onWatcherCleanup`：异步请求不再互相覆盖

```ts
import { onWatcherCleanup, watch } from 'vue'

watch(searchQuery, async (query) => {
  const controller = new AbortController()
  onWatcherCleanup(() => controller.abort())

  const response = await fetch(`/api/search?q=${encodeURIComponent(query)}`, {
    signal: controller.signal,
  })
  results.value = await response.json()
})
```

当查询词快速变化时，上一次请求应该失效。副作用清理与创建写在同一个 watcher 中，比在外部保存 controller 更容易审查，也减少旧请求覆盖新结果的问题。

同样的模式适用于事件监听、定时器和 observer。原则是：谁创建副作用，谁负责声明清理。

## 5. Lazy Hydration 说明了什么

3.5 为异步组件提供了延迟 Hydration 策略，可以按可见、空闲、媒体条件或交互触发。它主要服务 SSR 应用；纯 Vite SPA 不会因为使用这个 API 自动获得收益。

真正值得学习的是“按用户需要激活”的思路：首屏不需要的代码不应抢占主线程。SPA 中对应的实践仍然是路由懒加载、异步组件和把大型交互放到可见后初始化。

## 升级检查清单

- 锁定 Vue、编译器和语言工具的兼容版本；
- 运行类型检查、单元测试和生产构建；
- 检查 watcher 是否有未清理请求与计时器；
- 检查模板引用在挂载前为空的边界；
- SSR 项目额外验证 Hydration mismatch；
- 不在同一次升级中顺便重写全部组件。

Vue 3.5 的价值不在“语法更新”，而在让响应性、引用和副作用生命周期更明确。这些能力可以直接减少难复现的组件状态问题。
